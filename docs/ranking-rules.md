# 랭킹 규칙

inventory 서비스가 트렌드 하나를 과잉재고 상품 하나로 바꾸는 방법입니다. 여기 적은 규칙은 모두 코드이며 언어 모델은 부르지 않습니다.
`코드` 표기는 요청과 응답에 실제로 나오는 값입니다. 카테고리·색 이름은 trend 서비스의 표준 어휘를 따릅니다.

## trend 결과에서 쓰는 값

| trend 결과 필드 | 쓰는 곳 |
|---|---|
| `applied_filters.season` | 요청 시즌(필수). 사용자가 시즌을 말하지 않았으면 orchestrator의 질의 구조화 단계가 다음 시즌으로 정하고(`origin: default_next`), trend는 그 값을 그대로 담아 넘깁니다. 이 서비스는 값과 출처를 `season_basis`에 그대로 옮깁니다. |
| `applied_filters.categories.include` / `exclude` | 사용자 카테고리 / 제외 카테고리(`minor`, 없으면 `major`) |
| `applied_filters.attributes` 중 색 | 사용자 색(21색 이름). 소재·핏 같은 다른 사용자 속성은 쓰지 않습니다. |
| `applied_filters.gender` | 고객군(아래) |
| `trends[].items[]` | 트렌드 카테고리와 색, `similar_products`의 CLIP 기준 이미지 |
| `status` | `no_results` → DB를 조회하지 않고 `no_results`. `error`는 trend 결과 스키마가 허용하는 값이라 받으면 `INVALID_REQUEST`(`reason: upstream_error`)로 답합니다. trend는 검색 실패를 이 값 대신 HTTP 503으로 알리므로 정상 흐름에서는 오지 않습니다. |

트렌드 아이템 자신의 소재·핏으로는 재고를 거르지 않습니다. 기획할 상품은 새 상품이고, 그 소재에 맞춰 함께 입을 옷을 거르는 것은 코디 논리에 맞지 않기 때문입니다. 소재·질감은 CLIP 필터로만 반영합니다.

## 1. 짝 카테고리

영역은 `상의`, `하의`, `아우터`, `원피스` 네 개입니다. 세부 카테고리(예: `블라우스`)는 해당 영역으로 바꿉니다.

| 기획 영역 | 짝 |
|---|---|
| 상의 | 하의만 (사용자 규칙) |
| 하의 | 상의, 색 완화 뒤에도 상의 후보가 없을 때만 아우터 (사용자 규칙) |
| 아우터 | 상의, 하의, 원피스 |
| 원피스 | 아우터 |

- **사용자 카테고리 1개**는 위 표를 씁니다. 상의·하의의 단계 순서는 `AREA_PRIORITY`이고, 조회마다 찾은 영역을 기록하며 다음 단계로 넘어가면 limitations에 적습니다.
- **사용자 카테고리 여러 개**는 각 짝의 교집합, 교집합이 비면 합집합입니다.
- **사용자 카테고리 없음**은 트렌드 카테고리들의 짝 교집합입니다. 공통 짝이 없으면 트렌드 카테고리와 그 짝 전체를 찾고 순위로 고릅니다.
- **카테고리가 전혀 없고 색만 있음**은 네 영역 전체입니다.
- **제외 카테고리**: 영역이면 짝 영역에서 빼고, 세부 카테고리면 그 상품을 후보에서 뺍니다. 모르는 값이거나 사용자 카테고리와 겹치면 `INVALID_REQUEST`입니다. 빼고 나서 찾을 영역이 없으면 그 트렌드는 `no_results`입니다.
- 카테고리도 색도 없는 트렌드는 그 트렌드만 오류입니다.

## 2. 기준 색과 어울리는 색

**기준 색**(상품이 어울려야 하는 색)은 다음 순서로 정합니다.

1. 사용자 색이 있으면 사용자 색. 트렌드 아이템 전체의 색과 비교해 겹치는 사용자 색만 쓰고, 하나도 안 겹치면 사용자 색 전부를 씁니다. 두 경우 모두 `limitations`에 적습니다.
2. 없으면 사용자 카테고리 영역에 속한 트렌드 아이템의 색.
3. 없으면 트렌드 아이템 전체의 색.
4. 그것도 없으면 색 조건 없음(21색 전체).

**어울리는 색**: 21색마다 조합 색상표에서 기준 색 몇 개와 어울리는지 셉니다. 가장 많이 겹치는 색(동점은 모두)에 기준 색 자체(톤온톤)를 더합니다. 21색 이름으로 바꿀 수 없는 색은 빼고 `limitations`에 적습니다.

예: 기준 색이 핑크와 화이트면 그레이·스카이블루·베이지·네이비가 둘 다와 어울리므로(2개), 찾는 색은 이 네 색에 핑크와 화이트를 더한 여섯 색입니다.

## 3. 과잉재고 조회와 완화

조회 한 번은 읽기 전용 SQL 하나입니다. 짝 영역과 찾는 색에 속하고, 시즌에 맞으며(`article_attrs.season_fit`), 고객군에 속하고, 재고가 0보다 많은 상품을 재고 금액·판매율·시즌 판매 비중과 함께 돌려줍니다.

**고객군**: `여` → Ladieswear + Divided, `남` → Menswear + Divided, `공용` → 전체. 요청에 성별이 없으면 트렌드 아이템의 성별로 정합니다(여러 성별이면 합치고, `공용`이 있거나 모두 비면 전체). Divided는 젊은 층 남녀 공용 라인이라 양쪽에 넣습니다.

**후보가 0개면** 트렌드 색만 정해진 순서로 넓혀 다시 조회하고, 시도한 단계를 `search.color_attempts`와 `search.relaxed`에 남깁니다.

| `color_mode` | 찾는 색 |
|---|---|
| `max_overlap` | 가장 많이 겹치는 어울리는 색 + 기준 색(항상 처음) |
| `any` | 기준 색 하나라도와 어울리는 색 전부 + 기준 색(`max_overlap`과 같으면 건너뜀) |
| `none` | 색 조건 없음 |

사용자 색과 사용자 카테고리는 완화하지 않고 짝 영역도 넓히지 않습니다(하의 기획의 상의 → 아우터 단계만 예외). 모든 단계가 비면 그 트렌드는 `no_results`입니다.

## 4. 최근 판매 추세

데이터 마지막 날(2020-09-22)부터 거꾸로 세어 최근 4주와 그 직전 4주를 비교합니다.

- 상품 변화율 = (최근 + 1) ÷ (직전 + 1). 또래 변화율 = 같은 영역 후보 전체의 같은 값.
- `trend` = 상품 변화율 ÷ 또래 변화율 − 1, [−1, 1]로 자름. 또래와 비교해 9월이면 모든 여름 상품이 함께 줄어드는 계절 효과를 뺍니다.
- 8주 판매가 5개 미만이면 판단하지 않고 `trend = 0`.
- 영역 묶음 판매가 30개 미만이면 후보 전체를 또래로 씁니다.
- 추세 조회가 실패하면 `trend`를 중립으로 두고 결과를 `partial`로 하며 오류를 기록합니다.

## 5. CLIP 필터

트렌드 아이템과 소재·질감·디테일이 비슷해 보이는 상품으로 후보를 좁힙니다. 색은 일부러 보지 않습니다. 색은 조합 색상표가 이미 정했고, 색을 보는 유사도는 같은 색(톤온톤)만 높게 쳐서 색상표를 뒤집기 때문입니다.

- **기준 이미지**(사용자 카테고리 아이템, 없으면 아이템 전체에서): `score`가 가장 높은 착샷(`kind: snap_garment`, `multi_wearer_suspected` 표시된 사진 제외), 없으면 `score`가 가장 높은 상품 이미지(`kind: catalog_item`), 둘 다 없으면 필터 없음(`no_reference`).
- **임베딩**: OpenCLIP `ViT-B-32-quickgelu`, OpenAI 가중치. 이미지는 흑백으로 바꾸고, 텍스트는 트렌드 아이템의 소재·디테일 영어 대응어입니다(넥라인·칼라 제외). 모델이 영어로 학습됐기 때문입니다. 두 벡터를 0.6 × 이미지 벡터 + 0.4 × 텍스트 벡터로 합쳐 정규화합니다. 두 유사도 점수의 가중 평균이 아니라 벡터를 합치는 것입니다. 텍스트가 없으면 이미지만, 쓸 수 있는 이미지가 없으면 텍스트만 씁니다. 유사도는 정규화한 벡터의 내적입니다(인덱스는 float16로 저장하므로 코사인의 근사값).
- **후보** 임베딩은 같은 규칙(흑백 사진 + `article_attrs`의 소재 + 상품 설명에서 뽑은 디테일)으로 미리 만든 인덱스에서 읽습니다.
- **남기는 규칙**: 후보를 색별로 나눠 색마다 유사도 상위 10%(올림, 색마다 최소 1개)를 남깁니다. 고정 기준값은 기준 이미지마다 유사도 수준이 달라 쓰지 못했고, 전체 상위 10%는 흑백에 남은 밝기 차이로 밝은 색이 쏠려 남았습니다.
- **후보를 0개로 만들지 않습니다.** 필터를 걸 수 없거나(`no_index`, `no_match`, `no_model`, `no_query`) 기준 이미지를 열 수 없으면(`search.clip.image_skip`) 후보를 그대로 두고 이유를 남깁니다.

필터가 보장하지 않는 것:

- 흑백은 색상·채도를 없애지만 명도는 남깁니다. 이미지 전체를 임베딩하므로 소재·디테일만 반영된다고 보장할 수 없습니다.
- 남기는 규칙은 상대 기준입니다. 어떤 색에 후보가 1개면 유사도와 상관없이(코사인 −1이어도) 남으므로, "남았다"가 "비슷하다"는 뜻은 아닙니다.
- 인덱스에 없는 후보는 0점이라, 인덱스에 있고 유사도가 음수인 후보보다 높게 나옵니다.
- 이 필터가 코디 적합성을 높인다는 평가는 없습니다. 기대기 전에 CLIP 없는 경로(`no_index`)와 비교하세요.

## 6. 순위

지표마다 후보 안 백분위로 바꾼 뒤 같은 가중치(각 0.25)로 평균합니다.

| 지표 | 순위가 높아지는 방향 |
|---|---|
| 재고 금액(재고 × 판매가) | 클수록 |
| 판매율 | 낮을수록 |
| 최근 추세 | 많이 줄수록 |
| 시즌 비중(그 상품 판매 중 요청 시즌 달의 비중) | 클수록 |

동점은 `article_id` 순입니다. 시즌 비중이 없는 상품은 후보 중앙값을 씁니다.

## 7. 상품 선택과 설명

- 상품 사진이 있는 최상위 상품을 돌려줍니다(`rank`는 실제 순위이고, 위 순위에 사진이 없었으면 그 사실을 적습니다). 후보 전체에 사진이 없으면 1위를 `image: null`로 돌려줍니다.
- `reason`에는 고른 근거 수치(짝 근거, 색, 재고 금액, 판매율, 추세, 시즌 비중, 점수)가 들어가고, 합성 값은 `reason.data_nature`로 표시합니다.
- `summary`는 계산값만 채우는 문장 틀이며 합성 값에는 "(가상)"을 붙입니다.
- `evidence`에는 트렌드마다 데이터 출처를 적습니다. E-001 가상 재고, E-002 시즌 판매, E-003 최근 판매, E-004 상품 속성, E-005 상품 사진(돌려준 경우), E-006 CLIP 기준 이미지(쓴 경우).

판매 데이터는 2018-09-20부터 2020-09-22까지입니다. 요청한 미래 시즌은 데이터 안에 온전히 들어 있는 같은 시즌 전부로 바꿉니다.

| 요청 | 쓰는 기간 |
|---|---|
| SS(봄·여름) | 2019-03-01 ~ 2019-08-31, 2020-03-01 ~ 2020-08-31 |
| FW(가을·겨울) | 2019-09-01 ~ 2020-02-29 |
| 봄·여름·가을·겨울 | 해당 달, 온전한 시즌만(가을은 2019년만) |

판매 구성(비중)은 기간 전체를 합쳐 계산하고, 판매량을 비교할 때는 기간 수로 나눕니다. 2020년을 함께 쓰는 근거는 [ADR 0005](decisions/0005-same-season-from-both-years.md)에 있습니다.

## 가상 재고

데이터에는 판매 기록만 있고 재고와 판매가가 없어서 둘 다 합성합니다(`data_nature: sample`).

- 판매율 0.30~0.95: 같은 고객군·영역 안 판매량 백분위(인기)와 마지막 판매일의 최근성을 반씩 섞고 작은 잡음을 더합니다.
- 입고량 = 올림(누적 판매량 ÷ 판매율), 재고 = 입고량 − 누적 판매량.
- 한 번도 안 팔린 상품: 입고량 20~200 무작위, 재고 = 입고량, 판매율 0.
- 판매가 = 상품의 최고 정규화 가격 × 1,000,000원, 100원 단위 반올림, 3,000~300,000원으로 자름. 가격이 없으면 같은 고객군·영역 중앙값.
- 시드가 고정이라 같은 데이터면 같은 재고가 나옵니다. 판매율을 실제 판매에서 만들기 때문에 판매율 지표와 추세 지표가 함께 움직일 수 있습니다.
