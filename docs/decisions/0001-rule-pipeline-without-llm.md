# 0001 LLM 없이 규칙 파이프라인으로 처리한다

- 상태: 채택
- 날짜: 2026-11-14

## 배경

초기 버전은 도구를 호출하는 LLM(`gpt-4o-mini`)이 어떤 조회를 할지 고르고, 상품을 정하고, 이유를 썼습니다. 그런데 입력은 이미 구조화되어 있었고(trend 결과의 시즌·카테고리·색·성별), 도구 순서는 정해져 있었으며, 목표(과잉재고 순위)는 수식이었습니다. 모델의 설명은 도구가 돌려주지 않은 소재·핏·스타일 근거를 썼고, 프롬프트 수정이 세 번 이어졌습니다([트러블슈팅 T-DESIGN-01](../troubleshooting.md#t-design-01)).

## 결정

LLM을 뺍니다. `run_trend`가 유일한 경로입니다: 짝 카테고리, 색 매칭, SQL, 판매 추세, 선택적 CLIP 필터, 순위, 상품 선택. summary는 계산값으로 채우는 문장 틀입니다. 조회 결과가 없으면 트렌드 색만 정해진 순서로 완화하고, 사용자 색과 카테고리는 완화하지 않습니다. 모든 단계를 `search`와 `limitations`에 남깁니다.

## 결과

- 입력과 데이터가 같으면 결과도 같습니다(기준 이미지를 받지 못해 CLIP이 텍스트만 쓰는 경우는 예외).
- 요청 경로에 모델 API 키·비용·네트워크 호출이 없습니다.
- 설명이 덜 자연스럽고 자유로운 후속 질문에는 답하지 못합니다.
- 제거 전후의 비용·지연·추천 품질을 같은 데이터로 비교한 측정은 없습니다. 이 결정은 과제의 구조와 설명 오류에 근거하며, 벤치마크에 근거하지 않습니다.

## 검토한 대안

- 프롬프트를 더 엄격히 해서 LLM 유지: 세 번 시도했고, 수정마다 증상 하나만 막았습니다.
- 짧은 후보 목록의 문장만 LLM에 맡기기: 나중에 따로 검사하는 단계로 둘 수 있습니다. 지금 출력에는 필요하지 않습니다.
